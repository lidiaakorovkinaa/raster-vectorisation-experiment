# Методика измерений 1.0

Документ фиксирует, что именно измеряется и как воспроизвести результаты.

## 1. Вход и нормализация

1. Браузер применяет EXIF-ориентацию через `createImageBitmap(..., { imageOrientation: 'from-image' })`.
2. Изображение рисуется в canvas с фоном `background` (по умолчанию `#FFFFFF`); альфа-канал сводится на фон.
3. Длинная сторона ограничивается `maxSide` (в UI по умолчанию 1200 px, допустимо 256–3000).
4. Сервер повторно декодирует PNG, при необходимости уменьшает area-average фильтром, кодирует `source.png` и сохраняет SHA-256 исходника и нормализацию.
5. В worker передаётся **один и тот же RGBA-массив**. Декодирование и подготовка не входят в замеряемое время.

Для непрозрачных изображений фон композитинга метрик оценивается по рамке (медиана RGB). Это нужно, чтобы движки с прозрачным фоном, прежде всего Potrace, не получали ошибку за фон, которого не было в исходнике. Для изображений с альфой используется выбранный пользователем фон нормализации. Фактический фон сохраняется в `source.qualityBackground`.

## 2. Время

- Замер выполняется в отдельном `worker_threads`-потоке.
- Для каждого движка выполняется 1 прогревочный прогон (настраивается), затем `N` измеренных (1–9, по умолчанию 3).
- Порядок движков ротируется между раундами: `P→I→V`, `I→V→P`, `V→P→I`, …
- Эксперименты сериализуются глобальной очередью, чтобы параллельные запросы не искажали медианы.
- Таймер оборачивает только вызов движка и сериализацию SVG:

```text
t = performance.now() после вызова − перед вызовом
```

- Сохраняются все прогоны, медиана, среднее, min, max, стандартное отклонение и CV = σ/μ·100%.
- При CV > 20% интерфейс показывает предупреждение.
- Таймаут движка — 180 с; при превышении worker перезапускается, текущий движок помечается ошибкой, остальные продолжаются.

Абсолютные значения зависят от CPU, JIT и фоновой нагрузки. Корректно сравнивать движки внутри одного запуска.

## 3. Качество

Все SVG рендерятся `resvg 2.6.2` (WASM) при рабочем разрешении источника. Прозрачные пиксели композируются на `qualityBackground`. Сравнение идёт по RGB.

### RMSE, MAE, PSNR

```text
RMSE = sqrt( mean_p ( (R1−R2)² + (G1−G2)² + (B1−B2)² ) / 3 )
MAE  = mean_p ( |R1−R2| + |G1−G2| + |B1−B2| ) / 3
PSNR = 20 · log10(255 / RMSE),  RMSE=0 → 99 дБ
```

### SSIM

Яркость `Y = 0.2126R + 0.7152G + 0.0722B` (0–255). Гауссово окно 11×11, σ=1.5, разделимая свёртка с краевым расширением. Формула:

```text
SSIM = ((2μxμy + C1)(2σxy + C2)) / ((μx² + μy² + C1)(σx² + σy² + C2))
C1 = (0.01·255)², C2 = (0.03·255)²
```

Сохраняются среднее по карте и 5-й процентиль (устойчивость худших локальных участков).

### ΔE2000 / ΔE76

sRGB → линейный RGB → XYZ (D65) → CIELAB. ΔE76 — евклидово расстояние в Lab. ΔE2000 — CIEDE2000 с компенсациями светлоты, насыщенности и тона. Сохраняются среднее, 95-й процентиль и доля пикселей выше JND (2.3) и 5.

### Силуэт (маска Оцу)

Порог Оцу вычисляется по гистограмме яркости источника; к нему добавляется 1, чтобы строгое сравнение `< threshold` включало чисто чёрные пиксели. Маска источника — пиксели темнее порога (или светлее при `blackOnWhite=false`). Маска рендера — пиксели, отличающиеся от фона композитинга более чем на 30 (сумма |ΔR|+|ΔG|+|ΔB|).

```text
IoU = TP / (TP + FP + FN)
Dice = 2TP / (2TP + FP + FN)
```

Метрика показывается только для Potrace и бинарного VTracer. Для цветных движков она не рассчитывается, так как сравнение цветной заливки с бинарной маской не имеет однозначной интерпретации.

### Карты различий

- `heatmapFixed`: ΔE2000, фиксированная шкала 0–20 — для сравнения движков;
- `heatmap`: ΔE2000, авто-шкала по p99 для разглядывания слабых различий;
- `diff`: абсолютная RGB-разница с адаптивным множителем (p99);
- `ssim`: карта SSIM, красный — структурные расхождения.

## 4. Структура SVG

Разбор пути: команды `M/L/H/V/C/S/Q/T/A/Z`, подконтуры, опорные узлы, сегменты, контрольные точки, точность координат, длина (кривые — 16 отрезков на сегмент), bbox (по сэмплированным точкам), уникальные цвета, градиенты, число `<path>`. Трансформы групп и viewBox учитываются при пересчёте в пиксели.

Размер SVG — UTF-8 байты; gzip — zlib level 9; SHA-1 — от хранимого SVG. Детерминированность — совпадение SHA-1 всех измеренных прогонов.

## 5. Ограничения

- Potrace бинарный: цветовые метрики для него справочные.
- Параметры по умолчанию не оптимизированы под конкретный класс изображений.
- SSIM/ΔE чувствительны к разрешению; при уменьшении `maxSide` детали исчезают до трассировки.
- Тайминги несравнимы между разными машинами.
- Один эксперимент — не статистика; используйте серию и агрегаты.

## 6. Воспроизводимость

В `record.json` сохраняются версии движков, Node.js, ОС, CPU/RAM, хеши, параметры, разрешённый порог, все прогоны времени, окружение и методика. Кнопка **«Повторить»** создаёт независимую копию с тем же `source.png`; экспорт ZIP содержит HTML, CSV, JSON, LaTeX, SVG и PNG.
